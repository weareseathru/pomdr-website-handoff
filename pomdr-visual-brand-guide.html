The "Why"

Our UX Strategy

Empathize First

We design for the real person (an older adopter or a senior owner in a stressful moment), not the org chart. Their goals drive the layout. We frame each page as a "How Might We" problem to solve.

Surface Primary Actions

Applications (foster, Helping Paw) are never buried. Quick users tap the button and leave happy; detailed users read the prose below it.

Accessibility Floors

Older eyes lose acuity. We enforce WCAG 2.2 AA+: Body text minimum 16px (we use 17px-18px), 4.5:1 contrast, and large 44x44px touch targets. No hover-only traps.

The Palette

Color System

Two colors do all the work. Brand Blue carries actions and key headlines (blue means "available to adopt"), Brand Purple carries accents and secondary states (purple means "foster needed"). Everything else is white, warm off-white, ink, and tints or shades of these two. Buttons use the slightly deeper Blue 700 so white text clears the WCAG AA 4.5:1 contrast floor. Status is never shown by color alone, every state also carries a labeled dot.

Project Roadmap

Migration Status & Timeline

A simple, plain-English look at where we are, what's left, and how we get this redesign onto the live website safely.

Milestones

The Project Timeline

Phase 1: Discovery & UX Audit (Complete)
Understanding Our Users

We mapped out every page on the live site. We created strict design rules (like making text large enough to read easily and buttons big enough to tap) to ensure the site is built specifically for our senior adopters and donors.

Phase 2: Architecture (Complete)
The "Divi" Decision

We decided to keep the existing "Divi" website builder. Why? Because the POMDR staff already knows how to use it, and keeping it ensures that all our existing dog profiles, URLs, and donation forms keep working perfectly without starting from scratch.

Phase 3: Active Build (In Progress)
Building the New Pages

We are currently taking the beautiful new designs and dropping them into the Divi builder section-by-section. We've successfully completed the Homepage, Contact page, and the individual Dog Profile templates.

Phase 4: Dynamic Wiring (Upcoming)
Connecting the Live Data

This is where we connect the live database of adoptable dogs to the new visual design. We will also build Live Filtering (also known as AJAX). This is the technology that lets a user click "Small Dogs" and see the results instantly, without the page having to reload or blink.

Implementation Strategy

How We Build It (In Plain English)

Moving Code to Divi safely

Divi is a visual builder that lets staff drag and drop boxes. Sometimes, drag-and-drop builders can mess up custom code. Our solution is simple: we wrap our new designs in "Code Modules." Think of these as protective lockboxes. The design stays perfectly intact inside the box, but POMDR staff can still drag the entire box up or down to reorder the page easily.

The Paw Print Animation

We love the interactive paw prints that follow your mouse! To make sure they don't break the rest of the website's layout, we treat them like an invisible glass overlay. The paw prints happen on this "glass" layer that sits on top of the website, completely independent from the text and images underneath.

Automating the Build (The AI Advantage)

Manually creating 22 pages, clicking "Add Code Module" 100 times, and copying/pasting HTML by hand would take weeks of tedious labor. Instead, we will use AI to automate the entire transfer process in seconds.

The Proposed AI Solution:

  1. The AI Parser: We will write a small script that automatically scans our 22 static HTML pages and perfectly chops them up into individual sections.
  2. The Divi Translator: The script will automatically wrap those HTML sections into the exact native code that Divi reads in the background (known as [et_pb_code] shortcodes).
  3. Instant Injection: Instead of clicking buttons in the WordPress dashboard, we will use a developer tool called WP-CLI (WordPress Command Line) to instantly inject all 22 pre-built pages directly into the database.

The Result: The AI does the heavy lifting in seconds. A human developer simply logs in, reviews the pages to ensure they look perfect, and hits "Publish."

Risks

Obstacles & Solutions

The Top Menu Overlap

Our new homepage features a massive, beautiful photo right at the top. But WordPress usually forces a thick white menu bar above it.

Solution: We will tell WordPress to use a "Blank Page" template for the homepage, letting our photo stretch all the way to the top underneath a transparent menu.

Accessibility & Screen Readers

Website builders like Divi often generate messy background code that confuses screen readers (tools used by visually impaired users).

Solution: By using our protective "Code Modules", we bypass Divi's messy code entirely. This ensures the site remains 100% accessible and compliant for all users.

Connecting the Dog Database

Right now, the new dog cards are just placeholder pictures. We need them to automatically pull the real dogs (like Pebble or Buster) from the POMDR database.

Solution: We will rewrite a small piece of code (called a "shortcode") in the background. Once updated, every time the website asks for a list of dogs, it will automatically wrap them in our shiny new design.

Projected Completion: ~2 to 3 Weeks

We have 22 static pages left to safely transition into the Divi Builder. The hardest architectural decisions have already been made and resolved. The remaining time ensures everything is rigorously tested so that donation forms work flawlessly and adopters have a seamless, bug-free experience.
